## Q1. static 멤버변수를 클래스 선언부에 선언하고 **외부에서 다시 선언**하는 이유
 
### 핵심 개념
 
C++에서 클래스 선언부(`class { ... };`) 안의 코드는 **설계도(청사진)** 역할만 할 뿐,  
실제 메모리를 할당하지 않는다.
 
```cpp
class Person {
    static int sharedMoney;  // ← "이런 변수가 있다"는 선언만 함
};
```
 
위 코드만으로는 `sharedMoney`를 위한 **실제 메모리 공간**이 만들어지지 않는다.
 
### 왜 외부에서 다시 선언해야 하는가?
 
| 구분 | 역할 |
|------|------|
| 클래스 내부 선언 | 멤버의 **존재**를 컴파일러에게 알림 (선언) |
| 클래스 외부 선언 | 전역 공간에 **실제 메모리를 할당**하고 초기값 지정 (정의) |
 
```cpp
int Person::sharedMoney = 10;  // 전역 공간에 실제 메모리 할당 + 초기화
```
 
### 추가 이유: static 멤버의 생존 기간
 
- static 멤버는 **프로그램 시작~종료** 동안 존재해야 함
- 객체가 하나도 없어도 메모리에 존재해야 하므로 **전역 공간**에 할당
- 객체마다 따로 생기는 일반 멤버와 달리, 클래스 전체에서 **딱 하나만** 존재
### 요약
 
> 클래스 선언부는 **"이 멤버가 있다"고 알리는 역할**만 하며,  
> 실제 메모리 할당은 클래스 외부의 전역 선언을 통해 이루어진다.  
> 이는 static 멤버가 객체 생성 이전부터 프로그램 전체에서 하나만 존재해야 하기 때문이다.

## Q2. static 멤버 함수의 **구현부**에 `static` 키워드를 붙이면 안 되는 이유
 
### 잘못된 예시 (컴파일 오류)
 
```cpp
class Person {
    static void addShared(int n);  // 선언부: static OK
};
 
static void Person::addShared(int n) {  // ← 오류! static 중복 불가
    sharedMoney += n;
}
```
 
### 이유 1: C++ 언어 규칙
 
C++ 표준에서 `static` 키워드는 **클래스 선언부**에서만 사용하도록 규정되어 있다.  
구현부(정의부)에 `static`을 붙이면 **컴파일 오류**가 발생한다.
 
### 이유 2: `static`의 의미 충돌
 
C++에서 `static`은 **두 가지 다른 의미**를 가진다.
 
| 위치 | static의 의미 |
|------|--------------|
| 클래스 멤버 선언 | 클래스 전체에서 하나만 존재하는 멤버 |
| 전역/파일 범위 | 해당 파일 내에서만 접근 가능한 내부 연결(internal linkage) |
 
구현부에 `static`을 붙이면 컴파일러가 **파일 범위의 static 함수**로 해석할 수 있어  
의미가 달라지거나 충돌이 발생한다.
 
### 올바른 작성법
 
```cpp
// 선언부 (클래스 내부): static 사용
class Person {
    static void addShared(int n);
};
 
// 구현부 (클래스 외부): static 없이 작성
void Person::addShared(int n) {   // ← static 없음
    sharedMoney += n;
}
```
 
### 요약
 
> `static`은 **클래스 선언부에서만** 붙이고, 구현부에는 붙이지 않는다.  
> 구현부에 붙이면 C++ 언어 규칙 위반(컴파일 오류)이며,  
> `static` 키워드의 의미가 클래스 멤버용인지 파일 범위용인지 충돌하기 때문이다.
